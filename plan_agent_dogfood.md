# Plan: dogfooding — use the library as a newcomer agent would, on real engineering problems

Branch `feature/agent-dogfood`, based on `integration/next-level`.

## Why

Five branches have just changed how pipelines are written and checked (strict parser, snapshot / sweep / describe, controls from annotations, figures, heatmap colorbars, `interactive_pipe.draw`, the `interactive-pipe` command, a rewritten skill). Nobody has yet used all of it together to do real work. The goal of this branch is to find out whether an agent that knows only the skill can write concise, correct scientific visual-debugging tools — and to turn everything that goes wrong into a precise list.

## Method — this matters more than the output

1. Read ONLY `src/interactive_pipe/agent/build-interactive-pipeline/SKILL.md` first. Do not read the library source or the docs before writing an example. When the skill is not enough and you have to look something up, that is a finding: write down what was missing, where you found it.
2. For each example below: write it, run `describe`, take a snapshot, **read the PNG**, sweep one parameter, read it, fix. Keep a friction log as you go (in Status): every error message that did not tell you what to do, every surprise, every place where you wrote boilerplate that the library should have absorbed, every time the snapshot differed from what you expected, with the minimal reproducer.
3. Count for each example: lines of pipeline code (filters + pipeline, excluding data generation), number of iterations before the snapshot was right, number of look-ups outside the skill.

## Examples to write — `demo/gallery/`, one file each, synthetic data only (numpy; scipy only if already installed; no downloads, no new dependency)

Pick problems an engineer would really debug visually; each file under ~80 lines, runnable as a script with `gui="auto"`, each with a docstring saying what to look at:
1. **Camera ISP**: Bayer mosaic → demosaic → white balance → gamma, with an error map (colorbar, diverging) against the ground truth and a PSNR readout.
2. **Frequency-domain filtering**: image, its log-spectrum as a heatmap, a band-pass mask controlled by two radii, the filtered image; a matplotlib figure with the radial power profile.
3. **1D signal processing**: noisy chirp, FIR/IIR filter with cutoff and order controls; curves for the signals, a figure with the frequency response (magnitude and phase on twin axes).
4. **Detection overlay**: blobs on a noisy background, threshold + minimal area; boxes and labels with `draw`, a table of detections, precision / recall as text.
5. **Optimisation trace**: gradient descent variants on a 2D function; contour figure with the trajectory, loss curve; controls for learning rate, momentum, steps (`Literal` for the optimiser).
6. **Geometry / calibration**: a checkerboard warped by a homography plus lens distortion; controls for the distortion coefficients; residual vectors or an error heatmap.
7. **Control engineering**: step response of a second-order system with PID gains; curves for response and command, a figure with the Bode plot.
8. One of your choice where you expect the library to be a poor fit — to find the edges.

Use annotation controls in some examples and decorator controls in others; use sweeps to choose the default values and keep the sweep image of two or three examples for the docs.

### Friction log (most expensive first)

1. **One slider for two filters does not exist** (frequency band in `band_pass` + `radial_profile`, cutoff in `design` + `bode`, PID gains in `simulate` + `bode`; ~15 min). Declaring `band` in both filters gives two independent sliders (`band_pass.band`, `radial_profile.band`); giving both the same `name=` raises `Duplicate control name`; the docs say nothing. First workaround: write `context["band"]` in one filter, read it in the other (invisible to `describe`, order-dependent, invalidated wrongly by `cache=True`). Final pattern: a filter that only returns the controls, `band = choose_band()` with `return (band,)`, passed to both. Reproducer:
   ```python
   @interactive(band=RangeControl((0.1, 0.3), [0, 0.7]))
   def band_pass(f, band=(0.1, 0.3)): ...
   @interactive(band=RangeControl((0.1, 0.3), [0, 0.7]))
   def radial_profile(f, band=(0.1, 0.3)): ...   # -> two "band" sliders
   ```
   Proposed fix: an explicit shared control, e.g. `band = Control(..., name="band", shared=True)` reused by both decorators (same object → one widget), or same `name=` + identical declaration → one widget. Skill now documents the parameters-filter pattern.
2. **A filter returning a list is unpacked into outputs, and a 1-item list silently becomes its item** (detections as a list of dicts; ~10 min). The error for N≠1 items is excellent (it even gives `return (values,)`), but the behaviour depends on the data: 0 items → error, 1 item → the dict instead of the list, no error, 2+ → error. Reproducer (`gui=None`): `make()` returns `[dict(a=i) for i in range(n)]`, pipeline `dets = make(); txt = show(dets)`: `n=1` → `show` receives `{'a': 0}`; `n=0` → `FilterOutputError ... returned 0 value(s)`; `n=2` → `returned 2 values but the pipeline assigns 1 name(s)`. Proposed fix: only a tuple is unpacked; a list is one value (or: when the pipeline assigns one name, never unpack).
3. **Testing filters and getting raw outputs** (~10 min writing `test_gallery.py`). (a) A filter calling `layout.style` / `context[...]` raises `RuntimeError: Framework operation called outside of filter execution` when called as a plain function, so `compare(out, gt)` cannot be unit-tested even though decorated filters are otherwise plain functions; (b) a `gui="auto"` pipeline gives no way to get its outputs as arrays: `pipe.pipeline` is the GUI app and `pipe.pipeline.run(img)` raises `TypeError: InteractivePipeQT.run() takes 1 positional argument but 2 were given`; `snapshot(None)` returns only the rendered picture; (c) a headless pipeline whose `return` is one name returns a 1-tuple (`(y,) = pipe(x)`). Workaround: re-declare a `gui=None` pipeline in the test from the example's filters. Proposed fix: `layout.*` no-ops and `context` is a scratch dict outside a pipeline (maybe a debug log); `pipe.run(img, **params)` / `pipe.headless` on GUI-decorated functions returning the outputs; document (c) (done in the skill).
4. **Stateful pipelines make snapshots and sweeps silently wrong** (reaction-diffusion; ~8 min). With the state advanced in `context` on each run, a sweep's cells are not independent (each continues from the previous cell's state: all black), and `snapshot` shows `t=0` in the caption while the state is thousands of steps in. Reproducer: a filter `count(gain=1.0)` (slider declared, `gain` unused) doing `context["n"] = context.get("n", 0) + 1; return np.full((8, 8), context["n"] / 10)`; `[pipe.snapshot(None, gain=g).mean() for g in (1, 2, 3)]` gives three different pictures (63.3, 84.9, 105.7) though `gain` changes nothing. Proposed fix: snapshot / sweep restore the context like they restore parameters and layout (or warn when a filter writes a context key it also read); the skill now says to make the output a function of the controls and use the context as a cache keyed on them.
5. **Constructors not in the skill** (3 look-ups, ~6 min): `Curve([[x, y, style, label], ...], xlabel=, ylim=, grid=)`, `SingleCurve(..., linewidth=, alpha=)` (the default line is too thick for a dense signal), `Table(list_of_dicts | dict_of_lists, title=)`, `draw.boxes(color=[...])`, `draw.lines(img, (K, 2, 2))`, `draw.points(radius=, filled=False)`. Fixed in the skill.
6. **The "nothing detected" corner case crashes three times** (threshold at max; ~6 min): (a) `draw.boxes(img, np.zeros((0, 4)), color=[])` → `ValueError: Empty colour list` (zero marks with a per-mark colour list should draw nothing); (b) `snapshot` of a pipeline returning an empty `Table(dict(x=[], y=[]))` → matplotlib `ValueError: At least one argument from "cellColours" or "cellText" must be provided` (`headless/snapshot.py::_draw_table`); (c) `Table(dict(x=np.arange(3)))` → `TypeError: Dict input must have list values` (numpy columns refused). Workarounds in `blob_detection.py`: `color=[...] or None`, `"no detection"` instead of an empty table, `.tolist()`.
7. **Text readouts waste a cell** (~3 min): a `str` output takes a full grid cell with small text (PSNR, precision / recall). `Image(arr, title=f"PSNR {psnr:.2f} dB")` (also works for a 2D heatmap with `layout.style` colormap + colorbar) is much better; the skill now recommends it. Proposed: let a filter set a subtitle/metric next to an output without wrapping it.
8. **Colorbar details** (~4 min): `layout.style(..., unit="log10 |F|")` appends the unit to every tick label ("4.2 log10 |F|", unreadable): a colorbar label would be better; with `vmin=1.0` on data up to 4.2, the max label "4.2" overlaps the "4" tick and "1.0" is formatted differently from "2", "3" (`frequency_filtering` before `55c6d0b`, `vmin=1.0, colorbar=True`).
9. **Figures and curves side by side have different text sizes** (~3 min): a `Figure` is rasterised at its `figsize` then scaled to the cell, so a 5×4.5 in figure next to a `Curve` has text half as big; picking `figsize` is trial and error (`optimizer_trace`, `pid_control`). Proposed: rasterise at the cell size, or a constant pixels-per-inch.
10. **No log-scale slider** (learning rate): `log_lr` slider + `10**log_lr`, and the caption shows `log_lr=-2`, not `lr=0.01`. Proposed: `Annotated[float, (1e-4, 1e-1), "log"]` / `Control(..., scale="log")`.
11. **CLI after a filter error**: `interactive-pipe snapshot err.py` prints the pipeline error, then `no GUI-decorated pipeline was called by err.py (gui=None pipelines ... are not captured)` — wrong, it was called and failed (exit code 1 is right). Proposed: "pipeline 'p' raised, see above".
12. **CLI snapshot cannot set a parameter**: a `TimeControl` script always snapshots at `t=0` (seed only); `interactive-pipe snapshot script.py --set t=4` would help (the Python `snapshot(t=4)` works).
13.
